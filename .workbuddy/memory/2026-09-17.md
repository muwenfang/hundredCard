# 2026-09-17 第三轮：排查「点开始游戏后卡顿」

## 结论
打包后仍会有这一帧，但通常降到编辑器时的 1/3 ~ 1/5。
- **编辑器特有成因（打包后大幅减小）**：着色器变体现场编译、中文字形光栅化 + 系统字体回退、Mono JIT、Console 日志。
- **打包后完全不变**：14 次 Instantiate、Canvas 布局 + 网格重建。

## 判定依据（读 SampleScene.unity / CardUI.prefab 实测）
- `gamePanel` 的 `m_IsActive: 1`（场景里是**开启**的），`MainMenu` / `endPanel` / `totorial` 为 0。
  但 `GameManager.Start → InitializeGame → UIManager.InitializeUi → ShowMainMenu` 会在首帧渲染前把它关掉，
  所以整块 gamePanel **从未被渲染过** → 首次渲染成本全部压到「点开始游戏」那一帧。
- 场景：56 个 GameObject、43 个 CanvasRenderer、15 个 Text、10 个 Button、14 个 CardSlot、1 Canvas + GraphicRaycaster。
- **15 个 Text 全部引用内置字体（`m_Font: {fileID: 10102}`，动态字体）**，且文字含中文 → 需现场光栅化 + 系统字体回退。
- `handCardArea` 上挂 **HorizontalLayoutGroup**（场景里无 GridLayoutGroup / ContentSizeFitter；有 Horizontal/Vertical Scrollbar）。未挂任何 Mask。
- `CardUI.prefab` 每张卡 = 3 GameObject + 3 RectTransform + 3 CanvasRenderer + 6 组件
  （根 Image + CardUI + DragHandler；Text + **Shadow**；另有一个 Image 子物体）→ **14 张 = 42 个 GameObject、约 210 个对象/组件在 1 帧内创建**。

# 2026-09-17 第四轮：重写整套加分规则

## 需求
把「每组命中加 pointsPerMatch」改为「1 分底分 + 一整套条件加分」，
含 时机 / 数字种类 / 数列种类 / 长度重叠 / 公差公比 / 雀头 六类，共 20 条。

## 关键设计决策（用户需知）
1. **加分规则全部替换，不再有「每组 4/4/4/2 分」**。
   依据：「只要手牌能合规放置，玩家就会获得**1分**的底分」——若保留每组分，底分应为 15 而非 1。
   `SlotGroup.pointsPerMatch` 字段已删除（场景 YAML 残留 `pointsPerMatch: 4`，Unity 会忽略）；
   `GroupJudgeResult.awardedPoints` 也已删除。
2. **新增 `SequenceType.Pair`（雀头）**，2 槽组默认候选类型由 `{Special}` 改为 `{Pair}`
   （= 恰好 2 张且数字相同）。`Special`（1/100/质数）保留在枚举里但不再被默认使用。
   `MinimumValueCount(Pair) = 2`。
3. **合规闸门**：`IsLegalLayout` = 所有槽位放满 + 每条数列都命中至少一种类型 + 雀头两张相同。
   不合规 → 本次 0 分，且**所有加分项都不计算**（items 为空）。
4. **公差/公比是分层取值**：三条均相同只算 +20 / +100，**不叠加**「两条相同」的 +10 / +50。
5. **「恰好各一个」用一一对应判定**（`HasOneOfEachOfThreeKinds`，枚举 3! 种分配）：
   一条数列可能同时命中多类型（如 3 项的 2,4,6 既是等差又是斐波那契），允许它扮演任意一个角色。
   实测结论：**4 项时等差 / 等比 / 斐波那契三者两两互斥**（AP∩Fib 需 d=a 且 3d=2a → a=0；AP∩GP 需 r=1；
   GP∩Fib 需 b/a 为无理数），所以 4 槽组的命中集合实际恒为单一类型。
6. **拼合判定用「多值并集排序后判数列」**：三个等差拼 12 项 = 12 个值排序后是等差；
   两个等差拼 8 项同理；两个斐波那契拼 8 项 = 8 个值排序后满足斐波那契递推。
   重复数字会自动让拼合失败（等差 diff ≤ 0 → false）。
7. **「数字同属两条数列」按「不同的数字个数 × 6」**（同一个数字在同一条数列内重复只算一次）。
8. 底分判定用的是**全部已放置数字（3 条数列 + 雀头）**，例如「所有数都是质数」含雀头。

## 改动
- `Assets/scripts/SlotManager.cs`（重写）：
  - 新增 `ScoreRules`（20 条规则的常量集中处）、`SequenceLine` / `HandLayout` /
    `ScoreItem` / `HandScoreResult` / `SequenceType.Pair`。
  - 新增纯静态 `EvaluateHand(HandLayout, turnCount)`（全部加分的唯一实现）、
    `IsLegalLayout` / `IsPair` / `AllSameParity` / `AllPrimeNumbers` / `AllCompositeNumbers` /
    `AllMatchType` / `FilterByType` / `HasOneOfEachOfThreeKinds` / `ConcatValues` /
    `SameValuesIgnoringOrder` / `CountSharedValues` / `CommonDifference` /
    `TryGetCommonRatio`（分数约分，避免 4,6,9 的浮点误差）/ `AllSameCommonDifference` /
    `HasPairWithSameCommonDifference` / `AllSameCommonRatio` / `HasPairWithSameCommonRatio`。
  - `CalculateScore()` → `CalculateScore(int turnCount)`；新增 `ComposeSummary(逐组判定 + 加分明细)`。
  - `DescribeGroupResult` 去掉了 `+N`（本组不再单独加分）。
  - `SlotGroup.IsPairGroup`（SlotCount ≤ 2）。
- `Assets/scripts/GameManager.cs`：`Settle()` 改调 `CalculateScore(turnCount)`（为「第 1 回合 +100」）。

## 验证
- 离线类型检查：0 错误 0 警告。
- 离线逻辑回归：**59 项全部通过**。覆盖 20 条规则的正反例 + 不合规三种情形（雀头不等 / 有组未命中 / 未放满）
  + 公比分数化 + 结算文案精确比对。
  发现并修正了 1 处**测试自身**的错误期望（2,4,6,10 不是等差，10-6=4 ≠ 2），代码逻辑无误。
