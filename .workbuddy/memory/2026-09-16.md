# 2026-09-16

## Hundred Cards — 手牌拖拽逻辑复查与修复

用户要求核对三条：①拖到 handArea/slot 后放入该处；②点击槽位里的卡退回 handArea；
③拖到其它地方自动回 handArea。并要求「数据与 UI 的父节点设置不能不同步」。

### 复查结论（修改前）
- **②完全没实现**：`DragHandler` 只实现了 IBeginDragHandler/IDragHandler/IEndDragHandler，
  没有 `IPointerClickHandler`，点槽位里的卡没有任何反应。
- ①「检测 handArea」只是 `FindSlotAt` 返回 null 后的兜底，没有显式判定。
- ③可用，但兜底是 `originParent`。**危险点**：从槽位拖出时 originParent 就是那个槽位，
  而 OnBeginDrag 已经把槽位数据清空了 → 一旦手牌区没配，卡会被放回槽位画面里，
  但槽位认为自己是空的，正是用户担心的不同步。
- **数据/UI 不同步的具体缺陷**：
  - `CardSlot.Clear()` 只清 `currentCard`，不清 `card.currentSlot`（单向清理，容易被误用）。
  - `GameManager.ReturnCardToHand()` 不清 `card.currentSlot`，全靠调用方先清。
  - `ReturnCardToHand` 在 home==null 时提前 return，但此时调用方 `CardSlot.Place`
    已经把旧卡的引用清了 → 槽位空了、旧卡却还挂在槽位上。
  - `CardSlot.Place` 先写数据再搬 UI，`cardRect == null` 时数据改了 UI 没改。
  - **`ReturnCardToHand` 不还原锚点**：卡进槽位时被铺满（anchorMin=(0,0)、anchorMax=(1,1)、
    offset 全 0），退回手牌区若只 SetParent，卡会以「铺满整个手牌区」的尺寸出现。
    这是最容易被肉眼发现的不一致。
  - `OnBeginDrag` 在 rootCanvas 为 null 时仍会先清槽位数据，留下中间状态。

### 修改
- `CardUI.cs`
  - 新增手牌布局快照 `handAnchorMin/Max/handSizeDelta/handAnchoredPosition`
    + `CaptureHandLayout()`（Awake 时按 prefab 记一次）/ `RestoreHandLayout(rect)`。
  - 新增 `IsInSlot`；新增 `RestoreRaycastDefaults()`（按 prefab 原样还原射线，不再一律设 true）。
- `CardSlot.cs`
  - `Clear()` 改为**成对清空**（同时清 `card.currentSlot`），与 `Take()` 语义一致。
  - `Place()` 重排顺序：先校验 RectTransform → 旧卡退出手牌（失败则整体放弃、槽位保持原样）
    → 释放卡原先所在槽位 → 先搬 UI → 最后写数据。
- `GameManager.cs`
  - `ReturnCardToHand` 改为返回 `bool` 的**统一入口**：先校验（不满足则整体不动）
    → 清槽位双向引用 → 改父物体 + `RestoreHandLayout` → 补进 handCards。
  - 新增 `IsOverHandArea(screenPoint, eventCamera)`，显式检测手牌区。
  - `ConsumeSlottedCards` 改成先 `slot.Clear()` 再 `Destroy`。
- `DragHandler.cs`
  - 新增 `IPointerClickHandler` → `OnPointerClick`：左键 + 非拖拽中 + `card.currentSlot != null`
    才退回手牌（需求②）。
  - 新增 `dragging` 标志，防止 beginDrag 失败后 endDrag/drag 仍然执行。
  - `OnEndDrag`：先 `RestoreRaycastDefaults` → 槽位命中则 `Place` 并**后置校验**
    `card.currentSlot == target`（Place 可能放弃，不能把卡留在 Canvas 上悬空）
    → 否则一律走 `ReturnCardToHand` → 最后才兜底 `FallbackToOrigin()`。
  - 删除本类里重复的「改父物体」代码，改为只调 `CardSlot.Place` / `GameManager.ReturnCardToHand`。
  - `OnBeginDrag` 里 rootCanvas 为空直接放弃，不再只清数据不搬 UI。

### 关于「拖完松手被误判成点击」
拖动期间 `SetRaycastTarget(false)`，EventSystem 松手那一帧用的是「射线已关」的命中结果，
`pointerPress`(卡) 与 `pointerUpHandler`(卡下方物体) 对不上 → 不判为点击。
另外 `OnEndDrag` 比点击判定更晚执行，届时 `dragging` 仍为 true，`OnPointerClick` 里有 `if (dragging) return;`
作为第二重保险。两条机制任一成立即可，所以这里不需要额外处理。

### 场景现状（重要，2026-09-16 22:5x 读 SampleScene.unity 得到）
| 引用 | 状态 |
|---|---|
| UIManager 4 个面板 / scoreText / roundText / endMenuScoreText / endMenuDetailText / startGameButton | 已拖 |
| UIManager nextTurn / settle / continue / returnToMainMenu 按钮 | **未拖**（且 `autoBindButtons: 0`，用户自己在 Inspector 挂 OnClick） |
| GameManager.cardPrefab | **未拖**（fileID: 0） |
| GameManager.handCardArea | **未拖**（fileID: 0） |
| SlotManager 4 组的 container | **全未拖**（fileID: 0），slots 列表也是空的 |
| 场景里的 CardSlot 组件 | **0 个**（存的 `slotGroup` / `slot` 物体上都没挂） |

→ 逻辑改对了也跑不起来：不拖 cardPrefab/handCardArea，抽卡会直接报错；
没有 CardSlot，`FindSlotAt` 永远返回 null，拖拽只能回手牌。
Canvas 上有 GraphicRaycaster、场景有 EventSystem + StandaloneInputModule，这部分没问题。
