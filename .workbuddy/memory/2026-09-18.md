### 真凶定位：不是连线，是层级顺序 + 射线遮挡
`Canvas/tutorial/close` 的 OnClick **连线完全正确**
（`m_Target: Canvas/tutorial`、`m_MethodName: SetActive`、`m_Mode: 6`(Bool)、`m_BoolArgument: 0`），
问题在于**点击根本到不了这个按钮**：

uGUI 的点击 = 按 Graphic 的 depth 从高到低取第一个命中者；depth 由**同级顺序**决定
（同一父物体下**越靠后越上层**）。场景里 `Canvas/tutorial` 的子物体顺序是

```
close(idx 0)  →  Viewport(idx 1)  →  Scrollbar Horizontal(2)  →  Scrollbar Vertical(3)
```

`close` 排在**最底层**，而 `Viewport` 的 Image 是拉伸铺满的、`raycastTarget=1`
（`Mask.showMaskGraphic=0` 只是不画出来，照样挡射线），Content 里那个正文 Text 也一样。
**用真实 RectTransform 数值复算（`TEMP/hc_check/verify_close_block.py`）**：

| 物体 | 矩形（相对 tutorial 左下角） | 遮住 close? |
|---|---|---|
| close | x 1255.66→1340.04, y 841.20→917.79 | — |
| **Viewport** | x 0→1362.70, y 17→938.99 | **是** |
| **Content/Text (Legacy)** | x 63.71→1298.99, y −16955.15→869.37 | **是** |
| Scrollbar Horizontal | x 0→1362.70, y 0→20 | 否（在底部） |
| Scrollbar Vertical | x 1359.70→1379.70, y 17→938.99 | 否（x 不重叠） |

→ 所以「只把 Viewport 的 raycastTarget 关掉」**不够**（正文 Text 还在挡），
**唯一正解是把 close 提到同级最后一位**（`SetAsLastSibling`）。
`Canvas/forTeacher` 的 close 恰好排在最后（idx 3），所以那个面板现在能关 —— 同一个 bug 只暴露了一半。

  - 关键细节：`FindContentText()` **只在 `ScrollRect.content` 子树里找 Text**，
