需求来源：`C:\Users\Muwen\OneDrive\Desktop\HundredCard.txt`

### 交付的脚本（Assets/scripts/）
- `NumberCardData.cs` — 牌面定义（SO）。只读定义，运行时**不修改** number/canDraw，避免污染资产。
  新增静态 `IsPrimeNumber(int)` 与自检属性 `IsPrimeFlagConsistent`。
- `CardUI.cs`（新增，guid a1b2c3d4e5f6478899aabbccddeeff01）— 单卡视图层，持有 `NumberCardData`，
  把 `value` 写到 prefab 的 Text 上；`SetRaycastTarget()` 供拖拽期间关闭射线。
- `CardSlot.cs`（新增，guid b2c3d4e5f6a7485990aabbccddeeff02）— 槽位标记，记录 groupIndex / slotIndex /
  currentCard；`Place()` 支持顶替时把旧卡退回手牌。
- `DragHandler.cs` — 拖拽。**必须显式实现 IBeginDragHandler/IDragHandler/IEndDragHandler**，
  否则回调不会被 EventSystem 调用。命中判定用 `RectTransformUtility.RectangleContainsScreenPoint`，不依赖射线。
- `SlotManager.cs` — `SlotGroup`（可序列化）+ `SequenceType` 枚举；读卡 → 判定（等差/等比/质数/特殊）→ 计分。
  等比判定用整数交叉相乘（aᵢ² = aᵢ₋₁·aᵢ₊₁），支持 4,6,9 这类分数公比，无浮点误差。
- `GameManager.cs` — 主流程：InitializeGame / StartGame / NextTurn / Settle / GameOver / DrawCards / ReturnCardToHand。
  抽卡池用「同牌面放 2 份引用」表达剩余数量，抽走即从 List 移除。
- `UIManager.cs` — mainMenu / gamePanel / endMenu（结算与结束共用）/ ranking 四个面板互斥切换 + 分数与回合显示。

## 改版：UI 不再由代码生成，全部改为 Inspector 拖引用（用户要求）

用户要求：手牌区与 slot 的 UI 不生成，只给 public GameObject/Text 字段并做好数据连接。

### 改动
- **删除** `Assets/Editor/HundredCardsSceneSetup.cs` 及其 meta、以及遗留的 `Assets/Editor.meta`（整个
  Assets/Editor 目录移除）。场景层级完全交给用户在 Unity 里自己搭。
- `SlotManager.SlotGroup`：从「手工拖 14 个 CardSlot」改为 **container 自动收集**：
  `public GameObject container` + `List<CardSlot> slots`（container 非空时被自动覆盖）。
  `BuildSlots()` 用 `GetComponentsInChildren<CardSlot>(true)`（**必须带 true**，gamePanel 初始隐藏，
  否则一个都收不到），按 Hierarchy 顺序即读卡顺序。带 `[ContextMenu("重新扫描槽位")]`。
  4 组默认配置在字段初始化器里给好（等差/等比/质数/特殊，分值 4/4/4/2）。
- `SlotManager` 在 **Awake** 里 BuildSlots（Unity 保证所有 Awake 先于任何 Start，所以
  GameManager.Start → InitializeGame → ClearAllSlots 时槽位已就绪），并保留 `EnsureSlots()` 惰性兜底。
- `GameManager.handCardArea`：`Transform` → **`GameObject`**；新增只读属性 `HandAreaTransform`。
  新增 `ValidateWiring()`，把漏拖的引用一次性报到 Console。`ValidateWiring()` 会校验槽位总数是否为 14。
- `UIManager`：补齐 7 个 `Button` 字段（开始游戏/排行榜/下一回合/结算/继续/返回主菜单/排行榜返回），
  **点击事件由 `BindButtons()` 在 Awake 里用 AddListener 自动绑定**，Inspector 无需挂 OnClick。
  提供 `autoBindButtons` 开关（想手动挂就取消勾选，避免一次点击触发两次）。
- `CardSlot.Rect`：从 `{ get; private set; }` + Awake 赋值改为**惰性只读属性**。原因：槽位所在面板初始
  隐藏，未激活物体的 Awake 不执行，Rect 会是 null。

### 踩坑记录
- `CardSlot.Place()` 里残留 `if (Rect == null) Rect = ...`，改成只读属性后会报编译错误——已删。
- **本机可用的离线编译校验方法（重要，可复用）**：
  `dotnet` 在 `C:\Program Files\dotnet\dotnet`，但 Bash 里 `APPDATA`/`PROGRAMFILES` 为空会导致
  NuGet 报 `Value cannot be null. (Parameter 'path1')`，**必须先 export**：
  `APPDATA=C:\Users\Muwen\AppData\Roaming`、`PROGRAMFILES=C:\Program Files`、`HOMEDRIVE=C:`、`HOMEPATH=\Users\Muwen`。
  然后在 Unity 工程**之外**建一个临时 csproj（不要放进 Assets/，否则被 Unity 导入）：
  - `EnableDefaultCompileItems=false`，`<Compile Include="D:\unity\Hundred Cards\Assets\scripts\*.cs" />`
  - `<Reference Include="D:\unity\2022.3.62f3c1\Editor\Data\Managed\UnityEngine\UnityEngine.*.dll" />`
  - `<Reference Include="D:\unity\Hundred Cards\Library\ScriptAssemblies\UnityEngine.UI.dll" />`（Text/Button/
    Image/LayoutGroup/EventSystems 都在这一个 dll 里）
  即可完成真实的类型检查（本机 Unity 批处理会卡在资源刷新，这条路更可靠）。
  注意：直接调用 csc 会被沙箱安全策略拦截，走 `dotnet build` 不受影响。
